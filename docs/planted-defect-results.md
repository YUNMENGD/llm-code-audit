## 评测工具自身踩的两个坑（过程记录，论文"实验方法论"可用）

首跑报告 recall 1.0 但 3 个陷阱"破防"——**全部是评测 bug 不是引擎 bug**：
1. 行号簿记错位：`count("\n")+1` 预测块首行与 splitlines 实际差 1，
   导致相邻块告警串染进陷阱窗口；
2. 陷阱块紧邻缺陷块时 ±1 容差互相污染。
修正（锚点搜索 + 陷阱严格窗口）后 6/6 干净。教训：**植入实验对行号精度
极端敏感，评测器必须先于被测系统通过自校验**——这与我们"校验管线不信
模型自报行号"是同一设计哲学，LLM 层同理。

## 适用范围（诚实声明）

- recall=1.0 证明的是**规则语义覆盖无盲区 + 治理豁免不误伤**：17 类已知缺陷
  形态各自的 textbook 写法全部可检出，且六类正确防护写法零误报。
- 它**不代表**对混淆/多跳数据流/跨函数构造的缺陷同样 100%——那些形态
  超出正则+AST 局部语境的静态层能力，正是 LLM 定级层与调用图上下文
  存在的原因（分层设计的另一半理由）。
- ENG-002（TODO）不计入：三库真实 TODO 数百条，会淹没 29 条植入的信号，
  该规则的存在性由 bench-real 的 29 条真 TODO 标注（全 T）覆盖。

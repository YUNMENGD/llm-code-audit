## 3. 关键决策回顾（ADR 落地情况）

- **线性流程+插入式决策点**：优于全 Agent 编排——可复现、成本可控，一致性指标直接可测
- **静态先行+模型增强**：本轮最大赢家。双模型"已防护"的误报（subprocess 列表参数、
  realpath 校验后的路径），最终靠确定性正则守卫解决——**概率性约束不可靠时，用确定性校验兜底**
- **第一阶段只做 Python**：正确，接口已为多语言预留，未拖慢主线
- **成本闸门全生效**：并发（80s→~30s）、增量缓存（重复审零调用）、置信度分级、few-shot A/B

## 5. 第三阶段（2026.10—2026.11）任务书

**目标：系统完善与测试，产出结题实证材料**

- **A. 测试集工程化**：从 GitHub 采 20~30 个真实 Python 项目（SWE-bench/带 CVE 的历史提交），
  人工标注建"真实版 examples/bench"，输出正式 P/R/F1/一致性四指标表
- **B. 性能与边界**：大项目（万行级）压力测试、超时/限流/断点续审、成本实测（元/千行）
- **C. 报告与可用性**：HTML 报告美化（筛选/排序）、缺陷趋势对比（多轮审计 diff）、使用手册
- **D. 论文实证素材**：误报治理实验扩展为论文第 3 章（已有骨架：fp-governance-experiment.md），
  双模型一致率 0.455、few-shot 前后对比、缓存零损失稳定性等数据已备好
- **E. 结题材料**：技术报告、演示视频脚本、答辩 PPT 大纲（11 月中）
- **F. 演示级桌面应用**（弹性加分项，排在 A/B 之后启动，约 2~3 天）：
  第一档方案 = **FastAPI 薄封装 + pywebview 窗口套壳**，让评审看到"可安装可双击"的形态：
  1. `serve.py`：`POST /audit`（收文件/目录路径）→ 调现有 `audit_path()` → 返回 `AuditReport.to_json()`；引擎代码零改动（ICD §9 契约保证）
  2. 前端单页：拖拽上传 → 审计进度（把 CLI 的实时进度 print 改 SSE 推送）→ 渲染现有 HTML 报告（加筛选/排序控件，与 C 项复用）
  3. `desktop.py`：pywebview 把页面装成独立窗口（图标/标题/菜单），配置读写走同一 `.env` 机制
  - 明确不做：PyInstaller 分发安装物（体积/杀软误报/签名三坑，交付不需要）、原生 GUI 重写（负收益）、多语言审计（引擎范围外）
  - 验收：老师电脑上双击图标 → 拖入一个 py 文件 → 窗口内出报告，全程不开命令行
